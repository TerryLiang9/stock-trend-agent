# A 股五分类趋势与可配置模型权重设计

## 目标

把现有三分类趋势裁决升级为五分类研究结果，并提高均线基线模型的默认权重。用户可以在 Web 设置页修改四个技术模型的权重，后端统一校验、持久化并在后续预测中生效。

默认权重：

| 模型 | 默认权重 |
| --- | ---: |
| 均线基线 `moving_average` | 0.70 |
| 小波模型 `wavelet` | 0.10 |
| 历史相似日 `analog` | 0.10 |
| 六因子模型 `logistic_6f` | 0.10 |

本阶段不使用新闻、财经博主、散户情绪，不触发自动交易或生成买卖指令。

## 五分类契约

所有有效模型先转换为统一方向值：看多为 `+1`，中性为 `0`，看空为 `-1`。综合分采用实际生效权重、方向值与置信度计算：

```text
综合分 = Σ(实际生效权重 × 方向值 × 校准置信度)
```

综合分范围为 `[-1, 1]`，边界采用左闭右开，正负端点保持对称：

| 状态代码 | 中文名称 | 综合分区间 | 研究模式 |
| --- | --- | --- | --- |
| `strong_bullish_control` | 强多头控制 | `[0.60, 1.00]` | 只保留做多方向研究 |
| `weak_bullish_control` | 弱多头控制 | `[0.20, 0.60)` | 做多为主，降低强度 |
| `bull_bear_tug_of_war` | 多空拉锯 | `(-0.20, 0.20)` | 双向/观望研究 |
| `weak_bearish_control` | 弱空头控制 | `(-0.60, -0.20]` | 做空为主，降低强度 |
| `strong_bearish_control` | 强空头控制 | `[-1.00, -0.60]` | 只保留做空方向研究 |

边界值 `+0.20` 属于弱多头，`-0.20` 属于弱空头；只有严格位于两者之间时才是多空拉锯。

## 权重规则

- 四个配置权重必须分别位于 `[0, 1]`。
- 四项总和必须为 `1.0`，允许浮点误差不超过 `0.000001`。
- 均线基线权重必须大于任一单独研究模型权重，确保“均线为主、研究模型为辅”。
- 预测时只纳入执行成功、目标语义已经统一、置信度有效的模型。
- 单个研究模型失败时，将剩余有效模型的配置权重重新归一化为实际生效权重。
- 均线模型失败时数据质量门禁直接失败，不使用研究模型绕过基线。
- 结果同时保存 `configured_weights` 与 `effective_weights`，便于复盘。

## 模型目标统一

四个模型的裁决目标统一为“下一交易日收盘价相对当前数据截止价的方向”。适配器返回强类型标准信号，禁止继续通过字符串包含关系猜测方向。

- 均线：保留现有方向、分数和证据。
- 小波：显式映射“偏多/观望/偏空”。
- 历史相似日：显式映射 `UP/FLAT/DOWN`。
- 六因子：训练标签改为下一交易日收盘相对当前收盘，并根据中性收益带映射方向；不再使用“下一日收盘相对下一日开盘”的不同目标。

## 后端数据流

1. 从 ClickHouse 读取截至预测时点的 Tick 聚合分钟线或分钟线。
2. 数据质量门禁通过后冻结同一份行情快照。
3. 四个模型只读取该快照，返回统一标准信号。
4. 裁决器读取版本化权重，过滤失败模型并计算实际生效权重。
5. 计算综合分和五分类状态，保存各模型贡献明细。
6. API 返回五分类、解释、配置权重、实际权重及证据。
7. 次日收盘后继续用现有后验链路评估方向，不在本阶段自动改变用户权重。

## API 与兼容性

现有 `POST /api/v1/trend-forecast/runs` URL 保持不变。`target_date` 改为可选；未提供时由后端交易日历从 `as_of` 推导下一交易日，避免前端猜测节假日。裁决结果追加：

```json
{
  "trend_state": "strong_bullish_control",
  "trend_state_label": "强多头控制",
  "weighted_score": 0.68,
  "research_mode": "只保留做多方向研究",
  "configured_weights": {
    "moving_average": 0.7,
    "wavelet": 0.1,
    "analog": 0.1,
    "logistic_6f": 0.1
  },
  "effective_weights": {},
  "contributions": []
}
```

为避免破坏已有消费者，第一阶段保留 `direction`、`confidence`、`reason_code` 和 `signals`；`action` 固定为 `abstain`，明确表示研究模式不产生交易动作。

## Web 交互

设置页 Agent 分类增加“A 股趋势模型权重”组合编辑器：

- 四个数字输入框，显示百分比和值。
- 页面实时显示合计与“均线必须高于任一研究模型”的错误。
- 合计不是 100% 时禁止保存这一组配置。
- 保存仍复用现有系统配置 API、版本冲突控制和运行时重载机制。
- 权重设置显示中文解释，并提示“仅研究分析，不构成交易指令”。

新增“A 股趋势”页面：用户输入 A 股代码并触发一次研究预测，页面使用结果卡展示五分类名称、综合分、四个模型贡献和实际生效权重。颜色只作为辅助，文字标签必须独立可读；页面不提供下单入口。

## 异常与边界

- 权重配置非法：系统配置 API 返回字段级校验错误，旧配置继续生效。
- 研究模型失败：预测继续，结果中保留失败原因，并对有效权重重新归一化。
- 只有均线模型有效：仍生成五分类，但标记 `limited_evidence=true`，置信度仅来自均线。
- 均线或行情质量失败：整个预测失败，不生成伪分类。
- 综合分恰好等于阈值时按本设计的确定边界分类。
- 非有限数、缺失置信度和不统一目标的信号不得进入计算。

## 验证范围

- 后端单元测试：配置总和、均线主导约束、有效权重归一化、全部边界值、模型失败与单模型结果。
- 适配器测试：三个研究模型的显式方向映射和统一目标。
- API 测试：响应新增字段、旧字段兼容、运行记录可回放。
- Web 测试：默认值、实时合计、非法保存、合法保存、五分类结果展示。
- 回归检查：新闻未进入模型列表与裁决，订单服务未被调用。

## 非目标

- 不接入新闻、财经博主或散户情绪。
- 不实现动态自动调权。
- 不实现自动下单、仓位管理或止损。
- 不让大语言模型决定权重或五分类结果。
- 不在本阶段修改均线窗口等模型内部参数。
